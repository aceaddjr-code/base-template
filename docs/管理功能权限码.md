## 授权规则

- 在角色管理中勾选对应页面及操作。现有矩阵会在勾选动作时联动勾选页面和 `:view`，关闭查看时清除该页面动作。
- 普通角色可以获得任意明确授予的管理权限，不再要求角色编码为 `admin`。`admin` 保留既有系统管理例外。
- 用户管理两项动作（重置密码、退出全部登录）当前仍受用户控制器类级 admin 边界约束；重置与撤销均不允许以操作者本人为目标，本人改密/退出走自助流程。
- 发布、撤回与编辑是三个独立动作；编辑者不会因为能编辑而自动获得发布资格。
- 日志查看面向全站；已删除附件残留文件回收面向全站。分配这两项时应按实际审计和运维职责授权。
- 附件中心可见性双轨：文件库（附件管理直传）按「附件管理」数据范围（scopeKey `attachments`）控制；业务附件跟随所属单据的数据范围与查看权限——看不到那张单据就看不到它的附件。已挂接业务附件从单据详情管理，附件中心不提供删除。
- 修改角色授权后，现有服务会使相关用户旧会话失效；重新登录获取新权限。

## 基础阅读和单据文件

已发布公告阅读、按字典编码读取下拉选项（包括存量停用值回显）、个人资料和本人通知继续是登录后的基础能力。用户简表 `GET /users/simple` 同样登录即可读（仅启用用户的最小字段：账号、姓名、部门），业务单据的负责人候选与创建人/负责人姓名解析依赖它；完整用户列表及全部写操作仍限管理员。

公告管理详情使用 `GET /system/announcements/manage/:id`，由 `announcements:view` 保护；共享公告弹窗在管理页使用该接口。普通阅读仍走原详情接口，并保留发布状态判断。

示例单据临时文件上传改走 `POST /examples/items/attachments/upload`，使用 `example-items:update`。上传器与附件管理共用私有存储、大小和格式限制。文件上传后仍是当前用户所有的临时附件，挂接时由单据服务重新校验记录数据范围、他人编辑开关和文件归属。单据的文件列表、下载和删除仍使用既有单据权限。

示例单据的「变更负责人」是独立动作：`POST /examples/items/:id/owner` 使用 `example-items:owner`，在角色管理按需配置（admin 为系统例外天生可用）。负责人即记录归属人，变更后数据范围随之转移，修改日志留存当时姓名快照。

因此，只授权单据编辑即可继续使用单据附件；不需要额外开放附件管理页面。独立 `POST /attachments` 则要求 `attachments:upload`。

## 初始化和旧库升级

新库由 SeedService 初始化 19 个按钮节点（16 项管理操作＋用户管理三项），挂在五个对应页面下；默认普通业务角色不会获得这些管理权限。已有库重启不自动改写菜单或角色授权。

已有库按文件名顺序执行 `docs/sql/20261031-management-permissions.sql`、`docs/sql/20261104-account-security.sql` 与 `docs/sql/20261104-permission-explain.sql`（后两者分别还包含 users 待改密两列/登录限流计数表与纯权限节点）；执行顺序、备份和回滚见 `docs/sql/README.md`。补丁只向 admin 补授权，不自动向已有普通角色授予新操作权限。此前能进入附件管理的普通角色，升级后也需要管理员明确配置查看及对应动作。

上线必须配套发布前后端和执行数据补丁。仅在菜单管理中添加一个权限码，不会替代后端的权限校验。
