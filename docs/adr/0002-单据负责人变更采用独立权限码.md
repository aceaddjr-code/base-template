# 0002 — 单据负责人变更采用独立权限码

日期：2026-11-02 · 状态：已接受

## 背景

`BaseEntity.ownerId`（单据负责人）同时是数据范围的「记录归属人」，决定本人/他人口径。通用 CRUD（`crud-base.service.ts`）的既有规则是「只有系统管理员可以修改单据负责人」（`canEditOwner` 硬编码 `isSystemAdmin`），示例事项此前完全覆写了 create/update，负责人实际不可改派。

业务需要：负责人变更作为明确的管理动作，授权可由管理员在角色管理中按角色配置，而不是按角色写死业务资格（AGENTS.md 约定：不按角色中文名、职位或人员姓名写死业务资格）。

## 决策

1. 示例事项提供专用动作 `POST /examples/items/:id/owner`，权限码 `example-items:owner`，按钮节点挂在「示例事项」菜单下；前端在单据详情右上角以独立按钮进入，不混入字段编辑。
2. 不复用通用 update 通道改 `ownerId`：变更负责人即转移数据归属，属于指派类流程动作，保留专用交互（页面布局规范既有约定），且与普通编辑权限（`example-items:update`）解耦。
3. 通用层的 `canEditOwner`（仅系统管理员）继续适用于走 `CrudBaseService` 通用通道的模块；示例模块的权限码规则是其模块级特例，不改公共层行为。
4. 变更写单据事件（action `update`）与字段 diff，diff 存 ID 与事件发生时的姓名快照；负责人相同的提交记 no_change，不产生噪声履历。
5. admin 凭权限守卫的 `isSystemAdmin` 旁路天生可用；普通角色由角色管理显式勾选。种子对新库默认授予普通用户（与示例按钮既有口径一致），存量库补丁只授予 admin，由管理员再分配。

## 影响

- 权限最小化：只授编辑不给 owner 的角色看不到变更入口，接口 403。
- 数据范围随变更即时转移，修改日志可追溯「谁在何时把负责人从谁改成谁」。
- 第二个业务需要负责人改派时，评估把「权限码 + 专用端点 + 姓名快照 diff」提炼为共享能力，而不是复制本模块实现。
