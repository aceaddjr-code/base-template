# ADR-0001：附件挂接采用子表声明式

日期：2026-10-24 · 状态：已接受

## 背景

业务记录挂接附件（F08）曾同时存在两条互不相通的接缝，且**都没有任何真实业务接入**：

1. **运行时注册式**（已删除）：业务模块调用 `registerAttachmentTarget()` 登记实体类型与访问校验器，
   附件模块提供独立的 `POST /attachments/:id/bind`、`/unbind` 端点完成绑定，下载/删除按登记的校验器裁决。
   生产环境从未有过登记，`bind()` 恒抛「未登记的绑定目标类型」，前端也无任何调用。
2. **子表声明式**（保留）：业务模块在 `CrudBaseService` 构造时通过 `ChildSpec` 声明附件为自己的子表
   （`sourceKey` 指向附件表的来源关联列 `entity_id`，`sourceType` 写入来源标识），
   附件随业务记录同事务保存与软删除。该机制本身已有真实 MySQL 事务回滚测试（F05）。

## 决策

**子表声明式是业务记录挂接附件的唯一接缝**（2026-10-24 由项目负责人确认）。运行时注册式连同
`bind`/`unbind` 端点、注册表文件与相关测试一并删除。

理由：

- 新业务按仓库约定复制示例模块创建，天然继承 `CrudBaseService`，声明一行配置即接入；
- 附件生命周期（随主表同事务级联软删）已实现且有测试，注册式无对应机制；
- 访问裁决复用模板核心能力「数据范围」，不需要再维护一套每业务自定义的校验器。

## 后果

- 附件独立端点收敛为：上传（即 temp）、列表、授权下载、删除、过期清理；下载/删除仅上传者与管理员。
- `entity_type`/`entity_id` 两列语义改为子表声明式的来源标识与来源关联列，列注释已同步；无数据库结构变更。
- **演进点（首个真实业务接入时处理）**：
  1. 已绑定附件（bound）的业务可见性裁决——当前保守为仅上传者/管理员，接入后应随业务模块的数据范围判断；
  2. 父记录软删后 bound 附件行随之软删，但磁盘文件不清理——需要扩展 `sweepExpiredTemp`
     （F08 附件生命周期收尾）把「已软删来源」的 bound 行纳入清理。
- 未来架构审查不要再建议恢复运行时注册式；若确需脱离 `CrudBaseService` 的业务挂附件，
  先修订本 ADR 并给出第二个真实调用方。

## 增补（2026-11-02）：附件中心双页签与可见性双轨

附件管理页拆分为两个页签，`attachments` 新增 `origin`（center=附件管理直传 / business=业务表单上传）
与 `entity_title`（绑定时单据标题快照）两列：

- **文件库页签（origin=center）**：直传文件永久保留为独立文件，不可挂接到单据（挂接入口校验拒绝）；
  列表/下载/删除按附件管理自身数据范围（scopeKey=`attachments`，已在 SCOPE_FORM_REGISTRY 登记）裁决。
- **业务附件页签（origin=business）**：已挂接行的列表可见性与下载跟随所属单据的数据范围
  （上表演进点 1 就此裁决）；未挂接行为绑定中断的暂存，仅上传者可见可管理。
- **取消临时附件超期清理**：附件一律永久保留；回收任务（原 `sweepExpiredTemp`）收敛为 `sweepDeletedFiles`，
  只回收软删行的磁盘文件（演进点 2 的机制保留），`ATTACHMENT_TEMP_RETENTION_HOURS` 配置移除。
- 业务附件跟随单据数据范围的实现是 `modules/attachment/attachment-targets.registry.ts`：
  声明 sourceType/业务表名/scopeKey 的**静态常量元数据表**（列表 EXISTS 子查询与下载裁决用），
  不是恢复已删除的运行时注册式（无注册回调、无独立绑定端点）；新业务复制示例模块时登记一行，
  并有防漂移测试与业务模块常量对齐。

## 增补（2026-11-03）：独立删除的文件进入回收站

- 文件库文件、未挂接业务文件和单据内单独删除的附件，删除时保留文件并创建独立回收站记录；历史已删除文件不补录。
- 文件库遵循附件管理数据范围；已挂接附件遵循所属单据当前数据范围；未挂接文件仅上传者和管理员可管理。
- 独立删除的附件与随单据删除的附件分别记录；恢复单据不会恢复此前单独删除的附件。所属单据已删除时须先恢复单据；彻底删除单据之前须先处理其独立删除的附件。
- 定时清理仅清理未被回收站保留的历史软删除文件；回收站文件长期保留，直至用户彻底删除。

## 增补（2026-11-09）：附件入口的授权与诊断

- 文件库列表按附件管理的共同范围筛选。附件中心下载同时要求附件管理查看、文件库下载权限和对应的查看开关。删除使用附件管理的删除开关。
- 已挂接业务附件在附件中心额外要求附件管理查看权限，业务查看权限和数据范围与所属单据一致。单据内删除附件使用所属单据的编辑权限，同时要求查看开关。未挂接暂存文件继续按上传者隔离。
- 用户管理的「权限效果」选择附件管理并输入文件 ID，可诊断文件库、已挂接业务附件或独立文件回收站的操作。随单据删除的附件按单据回收站规则解释下载，恢复和彻底删除随单据执行。
- 通用上传只提供图片入口。原 `POST /common/upload/file` 已移除，业务文件通过附件管理或所属单据上传。
