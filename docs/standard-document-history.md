# 标准业务单据详情与履历接入

本次真实接入为示例事项。共享层只扩展已有详情、打印及离开保护交互；事件、动作、字段、字典规则和事务仍在示例业务模块。第二个真实业务接入后再判断是否提取共享写入能力。

## 按示例复制时的清单

1. 修改实体表名、模块路由、权限前缀、`scopeKey`、菜单、列表列偏好与筛选存储 key、Excel 列及测试名称。在 `scope-form.registry.ts` 注册范围。
2. 为业务定义明确的单据身份、对象摘要和动作码。事件只追加，保留操作人 ID、当时姓名、对象标题、服务端时间、来源、请求标识、版本和必要批次。历史不能随业务软删除或平台日志清理。
3. 列表、详情、履历、打印、编辑、删除和导出均使用同一范围查询后裁决动作开关。编辑要求查看资格；删除保持独立资格，不能顺带要求 view。自定义 POST 访问命令显式要求 view，不依赖 CRUD 方法名推断权限。
4. 写入路径采用模块自己的事务：锁定范围内当前行，校验版本，再比较实际规范化字段。业务、事件和差异同事务；不得捕获后吞掉履历错误。新增/导入也走同一已记录创建路径。事务外回读失败不能重做写入。
5. 明确追踪白名单及中文名称。示例仅追踪标题、状态、类别、说明，排除版本与技术时间等字段。秘密不入库；未来若有字段可见性，详情、事件摘要及 diff 都必须使用同一裁决。类型显示区分未填写、0、否及历史未记录；长文本完整存储并可展开。
6. 人员、字典和对象名称在事件发生时留安全快照。停用原值可保留，非法改选拒绝；旧历史缺失只说明未记录，不用当前值反推。迁移在应用发布前执行，保留表与历史的应用回退方式见 SQL。
7. 详情固定 detail/activity/operations/changes 四页签，支持全屏；首次打开用访问命令，重试沿用 interactionId。内部回读用普通 GET；切页签、全屏和日志读取不产生新查看。关闭重开和刷新生成新交互标识。
8. 打印先提交当前显示版本，服务端重新鉴权并登记 print/accepted，前端只打印受理返回的快照。复用 `DetailDrawer.preparePrint` 和字段白名单/转义；afterprint 只清理资源，取消不等于出纸成功。新的主动点击是新意图，失败重试保留原意图。访问命令用 `@SkipRequestAudit()` 排除 HTTP 方法推断，不在 common 层写业务路径；同一标记也用于原有自行记录审计的认证模块。
9. 履历查询只接受本模块的单据 ID 和白名单参数。动态按 occurredAt/id 游标倒序；表格以事件分页，同次查询上界稳定。以 eventId 定位前先鉴权单据，不能返回他单事件或数量。日期按 Asia/Shanghai 解释及显示。
10. 直达保留 `detail` 和合法 `tab`。示例页面独立消费持久定位；旧 `useDetailDeepLink` 的一次性消费行为仍供已有管理页使用。仅同一单据内导航保留编辑，关闭/切换记录及浏览器导航继续执行离开保护。缓存、请求代次及失败重试按单据隔离。

## 批量、导入和后续边界

批量删除每项独立事务，每次服务端请求生成一个 batchId；页面仅重试失败项会形成新批次。成功项不再次执行。导入重复预检零写入；确认导入每成功行一个 import 来源 create，失败行整体回滚。导入不承诺跨确认请求的文件级幂等。

当前动态仅有本单据事实，没有真实关联业务，也没有万能关联注册器。未来直接关联必须保留当时关系并校验来源对象的当前访问资格，不泄露隐藏标题、计数或旧值。附件继续遵循 ADR-0001 的子表声明式方式。

当前示例没有已声明子表。带 `ChildSpec` 的模块不能直接套用其无子表写实现；接入时必须保留原有声明式子表写入/软删，并与履历置于同一事务、验证整体回滚。
