回滚：DDL 隐式提交。未启用（配套代码未发布）按补丁逆序——先按备份与新增 ID 定向移除新增 `role_menus`/`menus`，再 `DROP TABLE login_attempt_counters`，确认无依赖后删两列；不回降 `token_version`。已启用后禁止直接回滚到不检查待改密标志的旧服务：先停登录流量、撤销相关会话、逐个处置仍有效的临时密码与待改密账号，回退代码验证后再恢复流量；删除结构是最后一步。详见补丁尾部注释与 `.scratch/account-security-phase1/migration-and-release.md`。

## 补丁账本与执行器（F13）

`scripts/migrate.mjs` 维护 `schema_migrations` 账本表（补丁名 + 内容校验和 + 执行时间），把本目录的 `YYYYMMDD-<slug>.sql` 按文件名顺序管理。命令（读取 `backend/.env`，可用环境变量覆盖 `DB_*`；备份需要 `MYSQLDUMP_BIN`，本机不在 PATH 时显式指定）：

```bash
node scripts/migrate.mjs status                # 已应用 / 待执行 / 文件被修改告警
node scripts/migrate.mjs up                    # 备份数据库 → 按顺序执行待执行补丁 → 逐个记账
node scripts/migrate.mjs mark-applied --yes    # 不执行，仅把补丁记为已应用
```

约定与边界：

- **执行顺序 = 文件名顺序**（日期前缀）。新增补丁只增不改：已应用的补丁文件再修改，`status` 会标记「文件已修改」，执行器不会重放。
- **`up` 执行前强制备份**（gzip 到 `BACKUP_DIR`，默认 `backups/`）；备份失败即中止，确属无需备份才可 `--skip-backup`。执行是逐个进行、成功一个记一条；某补丁失败即停止，其自带事务已自动回滚，否则按该补丁的回滚说明处理后核实数据库再重试。
- **`mark-applied` 只记账不执行**，仅适用于结构已是最新的数据库：全新库由 synchronize+seed 直接得到最终结构（含所有补丁效果），用 `mark-applied --yes` 一次性补记账；也可只记个别名称。对旧结构数据库误用会掩盖未执行的变更。
- 补丁分两类：`20261017` 是一次性旧结构迁移（只适用于精简版之前的数据库，全新数据库**不要执行**）；`20261021` 起为幂等补丁（可重复执行）。执行器不判断类别，操作者按下面各节说明选择 `up` 或 `mark-applied`。
- 全新生产库的结构基线（完整结构 SQL 导出）尚属待办，当前空库初始化依赖开发环境 synchronize 建表后再导出审查。

## 现有数据库升级到精简版

1. 确认有可用的本地管理员账号，停止写入，备份数据库及当前代码并检查可恢复性。升级期间使用 `NODE_ENV=production`，避免开发环境自动同步先删除旧列。
2. 在旧结构仍存在时执行 `20261017-local-accounts-and-user-scopes.sql`。它为从未配置用户级范围的账号迁移旧角色默认范围，并使已有登录失效；不覆盖已经配置的用户范围，不删除旧表、旧列或账号。
3. 部署精简版代码，以已有本地管理员登录。原外部身份账号需要管理员在用户管理中重设本地密码，然后才能登录；菜单、业务数据和原账号 ID 保留。
4. 在隔离环境验收登录、用户管理、角色授权、按用户/部门的数据范围、导入导出及二次启动。确认管理员自定义菜单和授权不被重写。
5. 旧身份字段、待开通表和角色范围表作为回滚资料暂留数据库。确认无需回退后，另建经审查的清理补丁；源码和新库不再包含这些实体。

补丁执行前失败可直接回滚事务；提交后需要恢复执行前数据库备份与对应代码版本。不要把回滚 SQL 与正向补丁放在同一个执行段。

数据库补丁必须加入版本控制；备份 SQL 和实际账号凭据继续忽略。
