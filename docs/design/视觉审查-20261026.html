定调复核：方向正确，四项支柱已立住三项

先把判断说清楚，避免把「我喜欢的风格」当成「该改的问题」。项目已有 DESIGN.md 与 style.css 两处一致的令牌定义，这在企业模板里相当少见。

支柱现状判定
Typography 全站单字体栈，中文显式回落雅黑；表格数字 tabular-nums 半兑现 — 字体文件从未加载
Color 暖白 #fdfcfc + 近黑 #201d1d，语义色走 Apple HIG 全套，比例接近 60/30/10 成立
Composition 无反白滥用，深色面只留给登录页与首页 hero；表格用发丝线做台账 成立
Motion 全库 0 个 @keyframes，0 个 animation 缺位

结论：不要引入新风格。极简／工业方向做到位就是高级，堆装饰反而是倒退。下面所有建议都在现有词汇内——发丝线、方括号、4px 圆角、单字体。

P0

执行力断层：用户一眼能看到

这五条不需要讨论风格，属于「写了但没生效」或「漏了一个页面」。

P0-1

字体身份从未落地，全站跑的是系统回退

style.css:6 首选项是 Berkeley Mono（商业字体，仓库未打包）；index.html 无任何一个 @font-face／字体链接；public/ 下只有图标。

Windows 上实际渲染成 Consolas（拉丁）+ 微软雅黑（中文）。后果是中英混排时字宽节奏断裂、中文失掉等宽气质，而这套设计 90% 的辨识度来自「整页像 man page」。这是全站性价比最高的一改。

改法 自托管 JetBrains Mono 400/500/700 三档 woff2 子集（拉丁+数字，约 90 KB），放 public/fonts/，font-display: swap 并 preload。中文继续走系统字体，但把顺序写死，避免不同机器漂移。 
/* style.css */
@font-face {
  font-family: 'JetBrains Mono';
  src: url('/fonts/jetbrains-mono-var.woff2') format('woff2');
  font-weight: 400 700;
  font-display: swap;
}
:root {
  --font-mono: 'JetBrains Mono', 'Noto Sans Mono CJK SC',
               'Microsoft YaHei UI', 'PingFang SC', monospace;
}

附带收益：App.vue 里 antd fontFamily 的同一串栈也只需跟着改一处（见 P2-1）。

P0-2

404 页整体脱离设计系统，且对比度只有 1.44:1

views/error/404.vue 全文 9 行，用 Tailwind 的 text-gray-300 / text-6xl / mb-4，没有 Page 外壳、没有 mono 语义、没有发丝线。

实测 #d1d5db 压在 #fdfcfc 上为 1.44:1，大字要求 ≥3:1，正文要求 ≥4.5:1——两个都不达标。结构上又是「居中数字 + 一行说明 + 一个按钮」，正好是审查清单里最典型的模板味。

改法 用现有词汇重写：方括号编号 + 发丝线 + 返回路径列表。既修对比度，也让它成为系统的延伸而不是例外。 
<!-- 404.vue -->
<main class="notfound">
  <p class="nf-code">[ 404 ]</p>
  <h1>这里没有页面</h1>
  <p class="nf-desc">地址可能已失效，或当前账号没有该模块的菜单权限。</p>
  <div class="nf-actions">
    <button class="nf-primary" @click="$router.push('/')">返回工作台</button>
    <button class="nf-ghost" @click="$router.push('/help')">打开帮助中心</button>
  </div>
</main>

/* .nf-code 用 --text-display 38px / 700 / 墨色，
   左侧 3px 墨条替代阴影表达层级；正文用 --color-text-secondary 9.78:1 */
P0-3

帮助页引用了 6 个并不存在的 CSS 变量

全库比对「组件使用 vs style.css 定义」，未定义的共 6 个，全部集中在 views/help/index.vue：--border-color、--border-strong、--bg-elevated、--bg-hover、--bg-fill、--text-secondary。

因为每条都写了十六进制兜底，页面看着正常——但等于把 #fdfcfc / #f1eeee / #424245 又抄了一份。换主题时这里不会跟着变，属于「静默失效」，比报错更难发现。

改法 逐一映射到真实令牌；顺手把 font-size: 18px、border-left: 3px、padding-left: 22px 这类裸值收进变量。
幽灵变量改为
--border-color--color-border-subtle
--border-strong--color-border-strong
--bg-elevated--color-surface
--bg-hover / --bg-fill--color-layer-hover / --color-layer-01
--text-secondary--color-text-secondary
P0-4

自定义滚动条几乎看不见（1.31:1）

style.css:224 滑块 rgba(15,0,0,0.12) 6px 宽。合成到暖白底后等效 #e0dede。

界面控件要求 ≥3:1。现在 1.31:1 意味着用户感知不到「这里还能往下滚」，而 .page-list 又把表格原生滚动条整段隐藏了，等于长列表失去唯一的滚动提示。

改法 background: rgba(15,0,0,0.28)（约 3.3:1），宽度 8px，hover 加深到 0.45。保留 track 透明。
P0-5

列表页骨架并不统一，四个页面对不上

逐页核对 page-list / PageToolbar / ListFooter 三件套的接入情况。

页面page-list工具栏页脚分页
examples/items✓✓✓
system/users✓✓✓
system/settings✗✗✗
system/attachments✓✗✓
system/menus · roles✓✓✗

缺 page-list 的页面拿不到台账外框、发丝线列分隔、隐藏横向滚动条；缺 ListFooter 的页面分页器随手放在表格下面，与内容一起滚走。用户会在「系统设置」和「用户管理」之间感到是两个产品的界面。

改法 优先补 system/settings（影响最大）；attachments 补工具栏；menus／roles 若数据量固定可保留内联分页，但需在 docs/页面布局规范.md 写明例外。
P1

品质补完：从「能用」到「讲究」

这些不修也能上线，但修完是明显的观感差。全部在现有令牌内完成，不引入新风格。

P1-1

零动效编排，页面切换是硬切

全库 @keyframes 0 个、animation 0 条，只有 antd 自带过渡与表格行 hover 的 160ms。

克制是对的，但「完全不动」和「到处都是 300ms 淡入上浮」一样廉价。企业后台最合适的量是：每次路由进入，页头与内容分两档错峰淡入，之后全程静止。不要给表格行、卡片单独加悬停动效——那样会变成噪音。

/* 一次编排，两档错峰，只动 opacity + translateY */
@media (prefers-reduced-motion: no-preference) {
  .starter-page-header { animation: rise 320ms var(--ease-out) both; }
  .starter-page-content { animation: rise 320ms 60ms var(--ease-out) both; }
}
@keyframes rise {
  from { opacity: 0; transform: translateY(8px); }
  to   { opacity: 1; transform: none; }
}

降级已由 style.css:584 的 prefers-reduced-motion 全局规则兜住，无需额外处理。

P1-2

首屏加载把整张表蒙成灰的

style.css:549 .ant-spin-blur { opacity: 0.4 }；全库没有任何 skeleton 组件。

首次进入列表页时表格里没有内容，blur 一片等于把浅灰背景再压暗一层，观感是「页面坏了」。区分两种加载：首屏空数据 → 骨架；已有数据刷新 → 保留 blur。

改法 在 .page-list 内判断 rows.length === 0 && loading，渲染 5 行 44px 占位条（background: var(--color-layer-01) + 1px 发丝线），不要再引第三方骨架库。
P1-3

标题与正文同尺寸，层级只靠字重撑

--text-heading: 16px 与 --text-body: 16px 完全相同；--text-title: 20px 之上就是 38px 的 display，中间断层。

单字体系统里，层级只能靠「尺寸 + 字重 + 留白」三件套。现在尺寸这一档是空的，h3 和正文长得一样，长文档（帮助页、开发者参考）读起来没有骨架。

改法 插一档 --text-heading: 18px（行高 1.35），h3 用它；h2 保持 20px。只加一行，不动其他调用点。
P1-4

中文长文行高 1.5，偏挤；而 1.7 的变量从未被用过

--lh-relaxed: 1.7 已定义但全库 0 处引用；正文统一 --lh-base: 1.5。只有 help/index.vue 里硬写了 line-height: 1.7。

中文没有词间空格，1.5 在 14–16px 下偏密。长段落（帮助正文、公告内容、详情里的说明字段、.table-long-text 多行说明）应统一 1.7；表格单元格、按钮、标签保持 1.5 不变。

P1-5

空态有三套口径

表格空态已重做（去掉插画、自动加 [ ] 包裹，style.css:202-207，做得很好）；但 home/index.vue 的 p.empty 是裸文本，详情抽屉空态又是 antd 默认 a-empty，通知面板的 a-empty 又没走表格那套样式。

改法 把方括号空态抽成一个 <EmptyState>（一句话说明 + 可选一个恢复动作），在 home、抽屉、通知面板三处替换。已经有三个真实调用方，符合项目「≥2 才抽」的约定。
P2

结构债务：现在不疼，改名换色时很疼

这几条不产生新的视觉问题，但决定了「下次美化」是改三个文件还是改三十个。

P2-1

色值有两个源：App.vue 硬编码，style.css 用变量

App.vue:14-58 里 40 余个十六进制字面量，与 style.css:4-46 一一重复；fontFamily 那串几十字符的字体栈也抄了两份。

后果已经可见：antd 的 colorLink 是墨色 #201d1d，而 CSS 里 --color-link 是 #0056b3，靠 .ant-btn-link 覆盖才勉强统一。下次调主色，必然只改一半。

改法 抽 src/design-tokens.ts 导出常量，style.css 用 CSS 变量（人读），App.vue 用 TS 常量（antd 要 JS 值），两边都从同一份 DESIGN.md 对齐。这是暗色模式的前置条件——令牌全在 :root，加一个 [data-theme="dark"] 覆盖块就能整体换肤。
P2-2

抽屉内部布局靠 :has() 猜 DOM 结构

style.css:245-336 约 90 行，用 :has(> .ant-spin-nested-loading):not(:has(.ant-card)):not(:has(.ant-tabs)) 之类选择器判断抽屉里装的是什么，配合 20 余处 !important（全文 101 处）。

这已经把抽屉内容锁死在特定 DOM 嵌套上：任何页面在抽屉里多套一层 div，内容就会被 overflow: hidden !important 裁掉且不报错。

改法 抽屉统一传 :body-style 或 root-class-name 上的语义类（如 drawer-body--form／--detail），由类名决定 flex 链，不再推断后代。可分两步：先给所有 <DetailDrawer> 使用者落类名，再删旧规则。
P2-3

公告行样式复制两份，已经漂移

home/index.vue:270-286 与 announcements/index.vue:67-81 几乎逐字相同，唯一差别是 padding: 10px 8px vs 12px 8px——同一个列表在首页和历史页行高不一样。

改法 抽 <AnnouncementRow>（title / time / click），两处复用。两个真实调用方，符合抽取门槛。
P2-4

Tailwind 只装了一半，且与令牌重复定义

style.css:1 引入 @import "tailwindcss"，但全库实际只用了几处：h-9! / w-9! / gap-2 / text-sm，以及 404 页那组 text-gray-*。

h-9!（36px）与 --control-h: 36px 是同一个值的两份来源。要么统一走 token、把工具类清掉；要么明确「布局用 Tailwind、颜色字号用 token」的边界。现在的状态是两套并存，谁也不知道该用哪个。

P2-5

部分触摸目标未达 44px

header 图标按钮 36×36（BasicLayout.vue:367）、.filter-remove 约 16px 宽（ListFilters.vue:41）、表格内 ant-btn-link 文字按钮。窄屏规则只把控件抬到 40px。

改法 窄屏把 --control-h-touch 从 40 提到 44，并给 header 图标按钮补 @media (max-width: 768px) { width: 44px; height: 44px }。.filter-remove 加 padding: 8px 用负 margin 抵消视觉偏移。
P2-6

文档头信息缺失

index.html 只有 title／charset／viewport／favicon；无 theme-color、无 description、无 color-scheme；public/ 同时存在 logo.ico 与 favicon.svg，只在 HTML 里用了 ico。

改法 补 <meta name="theme-color" content="#fdfcfc">（暗色主题时同步切换）、<meta name="color-scheme" content="light">；favicon 统一为 svg（现代浏览器）并保留 ico 作为回退。

建议的实施顺序：三批，风险递增

不建议一次全改。按「可见收益 / 回归风险」分三批，每批都能独立验收、独立上线。

批次 A

字体自托管 · 404 重写 · 帮助页幽灵变量 · 滚动条
四条都只动单个文件或单条规则，不改 DOM 结构。做完立刻能看到质感跳变。

风险：低
回归：视觉走查

批次 B

列表骨架统一 · 字阶补 18px · 中文行高 1.7 · 空态统一
涉及 3–5 个页面与 2 个共享组件，需要逐页比对 375 / 768 / 1440 三档。

风险：中
回归：三档截图对比

批次 C

动效编排 · 首屏骨架 · 令牌单源 · 抽屉 CSS 重构
最后一批。令牌单源是暗色模式的前置条件；抽屉重构需要把 13 个列表页都点一遍。

风险：中高
回归：全站功能走查
