# 列表筛选完善方案

> 已整合进[基础模板优化总方案](base-template-optimization-plan-20261020.md)。本文保留筛选交互细节与来源证据；当前范围、优先级和实施批次以总方案为准。

调研日期：2026-10-20。范围：本地现状、交互建议及 GitHub 一手参考；本文件不代表已实施功能。

## 推荐交互

统一为四层：常用条件、展开筛选、已选条件摘要、个人常用视图。默认紧凑展示，沿用现有暖白、墨色、细线主题和固定页脚，不另加大块装饰卡片。

| 层次 | 展示与行为 | 示例事项的第一版 |
|---|---|---|
| 常用条件 | 名称明确，条件少时直接可见；统一点击“查询”或 Enter 生效 | 关键词、状态多选、更新时间区间、查询、重置、展开筛选 |
| 更多条件 | 点击展开，隐藏后保留值；字段多的页面再使用面板，窄屏纵向排列 | 创建时间区间；仅使用现有实体字段，不添加虚构的业务字段 |
| 已选条件 | 显示已应用条件的中文标签、条件数量、后端匹配总数；支持逐项移除、清空 | “状态：待处理、进行中 ×”“更新时间：本月 ×” |
| 常用视图 | 保存并命名一组查询条件，可更新、重命名、删除、设为默认 | “本周待处理”“最近更新”；优先个人私有，不先做团队共享 |

视图属于查询方案，首版可以只保存条件和排序；列显隐/顺序/宽度沿用现有列偏好，不暗中覆盖。默认进入仍可使用“全部”，设置默认视图必须由用户明确操作。

### 字段与控件

| 字段类型 | 第一版交互 | 后续按需扩展 |
|---|---|---|
| 文本 | 关键词搜索；说明匹配哪些字段 | 指定字段“包含/等于/为空”，每个操作由后端白名单支持 |
| 状态/字典 | 多选、清空、选项较多时搜索 | 后端真实聚合的选项数量；不以当前页计数冒充总数 |
| 日期时间 | 起止范围、今天/近 7 天/本月快捷项 | 动态相对时间；保存“本月”应保存语义，每次应用重新计算 |
| 数值 | 最小值/最大值，允许单边区间和 0 | 金额、数量等具体业务存在时接入，不给示例虚构字段 |
| 人员/部门 | 仅在模块确有字段和后端授权查询时提供远程选择/树选 | 搜索、分页及明确是否包含子部门；不能把筛选部门等同扩大数据范围 |

日期按项目约定的业务时区处理，明确是否包含结束日。日期字段和时间戳字段分别转换边界；时间戳建议统一为起始包含、结束不包含的区间，不能直接将结束日期字符串当作当天结束。非法日期、开始大于结束、非有限数、数值下限大于上限均给出字段错误反馈。

### 生效规则

1. 输入条件是草稿；点击“查询”或 Enter 后生成已应用条件快照。标签、列表、总数、分页和导出都基于同一快照。输入未提交时不声称结果已经对应新条件。
2. “重置”回到模块基准条件并重新查询第一页；不自动套回个人默认视图，避免用户无法回到“全部”。后端规定的数据范围和模块固定业务条件始终保留。
3. 移除已选标签、选择已保存视图属于明确查询动作，应用后回第一页并清空勾选。若仍有未提交草稿，执行这些动作前提示草稿将被替换，不静默混合条件。
4. 第一版将状态的主筛选入口移到常用条件区，保留表头排序。若后续保留同字段的表头筛选，必须同步同一份查询状态，不维护两个互不联动的值。
5. 同字段多选是“任一符合”，不同字段是“同时符合”；关键词继续在模块登记字段内做 OR，再与其他字段条件 AND。任意嵌套“且/或”、跨关联表检索留到真实场景需要后实施。
6. 普通刷新保留条件及当前页；应用新条件回第一页。复用现有迟到请求保护，查询失败明确提示，不能把旧数据标成新条件的查询结果。
7. 无匹配结果展示当前条件和“清空筛选”入口。清空后无数据时使用普通空态。展开收起后重测表格可用高度，继续只保留页脚一条横向滚动条。

## 当前源码对照

- `frontend/src/views/examples/items/index.vue`：工具栏关键词，状态表头多选，部分字段排序；关键词有 appliedKeyword，统一 activeQuery 已被列表和导出复用，listVersion 防止迟到响应覆盖。应保留这些已有正确行为。
- `backend/src/modules/example/example.service.ts`：关键词查询标题/说明；只登记状态精确和 IN 筛选，未启用创建/更新时间范围。展示日期控件之前必须同时补白名单、查询参数类型与校验。
- `backend/src/common/services/crud-base.service.ts`：已有精确、IN、LIKE、日期及数值范围的配置能力；列表与导出共用查询构建。新增产品能力无需重写整个 CRUD，但不能将当前参数格式误称为任意操作符/分组查询协议。
- `frontend/src/components/PageToolbar.vue`：目前主要提供搜索框与插槽，没有完整的字段筛选表单、条件摘要或保存方案。`frontend/src/composables/useListPage.ts` 负责分页/滚动源，没有统一管理上述条件生命周期。
- `frontend/src/views/system/logs/index.vue`：自行实现关键词、类型、日期及重置，有的选择即请求、有的 Enter 后请求；作为第二个真实调用方可检验统一交互。
- `frontend/src/views/system/notifications/index.vue` 的 fetchData 在后端分页后使用 data.list.filter 过滤未读，再将当前页过滤后长度当总数。`notification.controller.ts` 列表未接收未读参数。这会造成当前页无未读就显示空结果，不能覆盖全部可见通知；属于应先修复的筛选正确性问题，本次仅做源码诊断，未执行运行时复现。

## 实施顺序与验收

1. **先统一正确性**：明确输入/已应用状态、条件序列化、重置与分页；未读筛选下推后端并在同一条件下统计 total。新条件、列表、导出保持同一权限与数据范围。
2. **再完善第一版交互**：示例事项与日志两个真实列表先落常用条件、折叠区、日期快捷项和条件标签；两处验证后提炼共享筛选组件/状态。保留 Page、PageToolbar、ListFooter、useResizableColumns，不替换表格库。
3. **再加常用视图**：按账号和页面隔离；先明确本机保存或后端跨设备同步，再实现其一。定义结构版本及字段失效提示，只保存允许的查询字段，不保存访问令牌、授权结果或敏感个人信息到 URL。共享视图后续独立设计权限。
4. **最后考虑复杂条件**：出现两个真实业务需求后，再增加受限制的操作符或分组表达式。服务端限制字段、操作符、条件数量、数组长度和嵌套深度，使用参数化 SQL；不接收任意 SQL/列名/表达式。

验收覆盖：多状态组合、单边/双边日期、结束日末尾数据、无条件/无匹配、重置、连续快速查询、分页回退、保存方案过期及账号切换；通用组件还需检查窄屏、收起后条件仍生效、表格高度和页脚横滚。日期快捷项的显示标签与实际范围必须一致。涉及数值时覆盖 0 和非法区间；筛选导出应命中相同条件下的完整集合，而不是只导出屏幕这一页。

本轮只新增此方案文档，未修改应用代码或安装依赖，因此未运行应用构建/测试。目录当前没有 `.git`，不能提供仓库级 git diff/status；实施前仍需保护已有文件改动。

## GitHub 一手参考

以下均经 GitHub connector 读取固定提交的官方仓库文件。借鉴交互和状态边界，不要求替换本项目组件库。

### 1. Vue Vben Admin：搜索表单与远程列表协作

固定提交：`61c07936c73b88fbcd1295958f443493cba825fc`。

- [表格封装源码：use-vxe-grid.vue](https://github.com/vbenjs/vue-vben-admin/blob/61c07936c73b88fbcd1295958f443493cba825fc/packages/effects/plugins/src/vxe-table/use-vxe-grid.vue#L124)：提交时读取表单值，保存最近提交值，再调用列表 reload；重置时比较重置前后值，兼顾 submitOnChange，避免重复刷新。默认提供展开收起按钮和随屏宽变化的表单栅格。
- [官方表格文档](https://github.com/vbenjs/vue-vben-admin/blob/61c07936c73b88fbcd1295958f443493cba825fc/docs/src/components/common-ui/vben-vxe-table.md)：搜索区采用独立表单，工具栏可控制面板显隐；reload 重置分页，query 保留当前分页。

可借鉴：将输入中的条件与已经应用的条件区分；查询回第一页，普通刷新保留页码；允许隐藏搜索区，但隐藏不应悄悄清空已应用条件。

### 2. Ant Design Pro Components：完整查询与轻量筛选

固定提交：`3bf43278d39f2d31489749132982488f57a9eb5e`。该项目使用 React，本项目只参考交互。

- [QueryFilter / LightFilter 官方说明](https://github.com/ant-design/pro-components/blob/3bf43278d39f2d31489749132982488f57a9eb5e/site/zh-CN/components/query-filter.mdx)：QueryFilter 支持默认收起、指定可见项数、响应式布局及保留收起字段值；LightFilter 提供多选、树选、级联、日期范围、数字等字段形态。
- [QueryFilter 折叠处理源码](https://github.com/ant-design/pro-components/blob/3bf43278d39f2d31489749132982488f57a9eb5e/src/form/layouts/QueryFilter/processQueryFilterItems.ts)：折叠隐藏与字段值保留有独立配置，布局按实际可见项计算。
- [LightFilter 源码](https://github.com/ant-design/pro-components/blob/3bf43278d39f2d31489749132982488f57a9eb5e/src/form/layouts/LightFilter/index.tsx)：次要字段归入“更多筛选”；该弹层用 moreValues 暂存输入，确认才提交，重置恢复初始值。常驻字段走即时提交路径。

可借鉴：常用条件直接显示、低频条件收起；复杂面板提供明确的应用操作。不要让同一页面的生效方式无提示地混用。

### 3. TanStack Table：筛选状态与服务端边界

固定提交：`95c4768496c07b45b1e65d8e33c3291ac66eae9b`。只借鉴原则，不据此要求引入其库或迁移 API。

- [Vue 列筛选指南](https://github.com/TanStack/table/blob/95c4768496c07b45b1e65d8e33c3291ac66eae9b/docs/framework/vue/guide/column-filtering.md)：列条件由字段标识和值组成，可同时存在多个；状态可以由应用受控管理，并提供读取、更新、清空及判断列是否处于筛选状态的接口。
- [Vue 全局筛选指南](https://github.com/TanStack/table/blob/95c4768496c07b45b1e65d8e33c3291ac66eae9b/docs/framework/vue/guide/global-filtering.md)：筛选应与分页、排序作用于同一数据集。仅加载一页时应交给服务端筛选；manualFiltering 不会替服务端执行过滤，也不能依赖前端行模型自动重置分页。

可借鉴：关键词、字段条件、排序和分页使用一份已应用查询状态，服务端完成权限范围内的过滤；筛选变化主动回第一页，避免只筛当前页产生误导。

## 参考与本项目建议的区别

- 上述文件证明展开收起、字段控件、草稿确认、状态管理和服务端过滤边界；未据此确认这些项目自带“保存我的筛选方案”或统一的“已选条件标签栏”。
- 条件标签、个人筛选方案、近期常用时间段和跨页面状态恢复，可作为本模板的产品建议单独设计，不能写成这些参考项目均已实现的功能。
- 如果保存筛选方案，保存的是允许的查询参数，不是授权结果；读取和应用方案后仍必须重新执行后端字段白名单、权限与数据范围校验。
