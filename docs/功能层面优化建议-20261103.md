# 企业管理系统基础模板功能优化建议（修订版）

初稿：2026-11-03；修订：2026-11-04。

本文为候选能力及实施顺序。现状依据修订时工作区源码及 ADR，不代表部署或生产验收结果。本次交付为方案与任务，未开始功能开发。

## 1. 建设原则

优先补齐账号、授权和数据恢复流程，再改善操作体验。每项以真实场景、最小范围和可观察验收结果决定是否建设。业务状态与资格由业务模块拥有；两个真实调用方出现后再提取公共能力。权限、数据范围与状态由后端裁决。工期在任务拆分和技术核对后估算，不承诺未经测量的效率提升或合规结论。

## 3. 第一批：账号安全闭环

**已有能力**：登录 IP 限流、JWT 校验、本人改密、管理员用户管理、Token 版本失效。

**真实场景**：同一账号被轮换 IP 猜测密码；初始或重置密码长期沿用；管理员需要撤销账号已签发的全部凭据。

**最小范围**：

1. 账号与 IP 联合限流，有界等待及自动恢复，多实例计数一致，避免账号存在性泄露。
2. 新建账号和管理员重置生成临时密码，登录后必须修改；重置作为独立管理动作。
3. 后端限制待改密账号：只允许最小会话信息、本人改密和退出，不依赖前端跳转。
4. 改密成功清除待改密状态、递增 Token 版本并重新登录。
5. 管理员撤销目标账号全部会话，保留账号启用状态和密码，记录审计。

**验收标准**：并发、多 IP、两个服务实例下限流有效；升级不无差别锁住存量账号；临时密码过期有反馈；Cookie/Bearer 直连不能绕过改密限制；重置及撤销后旧凭据后续请求被拒绝；日志无密码和 Token。

本批不含验证码、单设备会话、在线列表、后登踢先登、密码定期过期、MFA 或统一身份认证。限流降低风险，不承诺彻底杜绝爆破。强退不承诺实时关闭页面或取消已开始的业务事务。

实施入口：[第一批规格及任务索引](../.scratch/account-security-phase1/spec.md)；后续批次见[功能优化实施总索引](功能优化实施索引-20261104.md)。按仓库约定，任务保存在被 Git 忽略的本机目录；跨机器交接需交付整个目录。

## 4. 后续近期建设

| 项目 | 已有能力与真实场景 | 最小范围 | 验收标准 |
| --- | --- | --- | --- |
| 权限效果解释 | 已有操作权限、共同范围和操作开关；管理员难以解释某用户为何不能操作 | 选择用户与模块，展示有效权限及来源；对指定记录解释拒绝原因；复用实际后端裁决 | 与列表、详情、修改、删除、导出一致；解释会话更新时点；查询本身受授权 |
| 备份恢复闭环 | 已有数据库备份；故障恢复时还需要附件与配置 | 明确数据库、文件和必要配置的备份边界、一致性、保留期、异地保存、失败告警及恢复步骤 | 隔离恢复后单据、履历、附件和权限有效；记录数据丢失与恢复耗时目标及实测 |
| 导入预检查及错误文件 | 已有预检、逐行导入与部分成功反馈；大量错误行难定位，重试可能重复 | 先接示例事项，保留部分成功，补原始行列、错误文件和幂等确认 | 正式提交重新校验；错误可定位；重试不重复创建成功行；错误文件受授权，不传播不必要的公式、宏 |
| 通知可靠性与实时反馈 | 已有站内信和未读数，当前尚无业务生产调用；后续需要可靠反馈业务结果 | 先接负责人变更通知新负责人，落实事务一致性、幂等及失败重试，再接 SSE 与断线重新拉取 | 断线和重启不丢已持久化消息，不重复计数；失效会话停止推送；代理可用且能降级刷新 |
| 系统参数扩展 | 已有参数注册表；真实开关、数值和品牌配置需要适合控件 | 按需增加 boolean/number/select/image；定义范围、默认值、公开性、权限、生效时间及审计 | 非法值后端拒绝；多实例生效一致；公开接口无敏感配置；上传限制与代理一致 |

通知先接真实业务，出现第二个真实通道再评估多通道接口。数据库密码、JWT 密钥和全员共享默认密码不进入普通系统参数。

## 5. 按业务与测量结果触发

| 项目 | 已有能力与触发场景 | 最小范围 | 验收标准 |
| --- | --- | --- | --- |
| 异步导出/下载中心 | 已有同步导出；实测耗时、内存或并发超过目标 | 单模块任务持久化、分批读取、并发限制、重试和文件到期处理；明确生成及下载时的权限复核和数据时间口径 | 重启可恢复；重复执行不重复交付；权限收回后不能下载受限文件；资源占用达标 |
| 字段权限与脱敏 | 已有记录级授权；真实出现薪资、底价等敏感字段时优先推进 | 分开定义可见与可改；覆盖列表、详情、导出、履历、快照与派生内容 | 任一入口均不能越权读取或修改；查看明文及二次验证语义明确 |
| 离职、调岗交接 | 已有禁用账号和负责人变更；未完成单据需要移交 | 单模块待交接清单、接收资格校验、逐条结果与审计 | 历史归属保留；失败可定位和重试；复用模块负责人变更权限 |
| 岗位 | 已有角色与部门；真实需要按岗位找人或分配任务 | 岗位人员关系；分别定义展示、指派和授权用途 | 调岗候选正确，授权显式可追溯，不按岗位中文名隐式增权 |
| 多部门 | 当前单部门字段；出现兼职场景 | 明确主/兼任部门、范围合并、记录归属及历史数据规则 | 各入口一致；退出兼任部门后按规则收回权限 |
| 树形字典 | 已有平面字典及排序；出现真实多级分类 | 父子关系与树形选择，明确移动、停用和删除语义 | 防环、排序、历史值显示正确；平面字典保持可用 |
| 密码强度与 MFA | 当前最低 3 位；面向外网或更高保护要求时评估 | 统一长度/弱密码校验与存量迁移；管理员 MFA 另立规格 | 各密码入口一致；旧账号有明确迁移和恢复路径 |

异步阈值根据查询、字段宽度、并发和资源实测确定，不固定为 2,000 条。已有敏感字段时，字段权限应前移。

密码策略参考 [NIST SP 800-63B-4](https://pages.nist.gov/800-63-4/sp800-63b/authenticators/)：重视长度、常见及泄露密码拦截，不默认采用强制字符组合或周期换密。此参考不代表符合中国等保或其他认证；最低 3 位是现状，不是安全推荐。

## 6. 等待复用证据的能力

| 项目 | 建设条件 | 最小范围与边界 | 验收标准 |
| --- | --- | --- | --- |
| 流转/审批复用 | 两个真实业务出现稳定共性 | 复用权限、事务、版本检查及履历；状态、审批资格和撤回条件留在业务模块 | 各业务规则独立正确；并发审批不重复生效；前后端一致 |
| 回收站复用 | 第二个真实业务接入 | 沿用 ADR-0001/0003；提取稳定协议，编号和恢复条件由模块拥有 | 竞态、缺失文件、编号占用、失败重试及数据范围通过验证 |
| 可视化定时任务 | 多个真实任务需要人工管理 | 只管理代码预注册任务；先做运行历史、补跑、互斥和告警 | 多实例不重复执行；补跑幂等；Cron/时区/错过执行规则明确；不接受任意代码或命令 |
| 运维监控页面 | 现有健康检查不能满足真实排障 | 先定义指标和告警，再选择复用部署监控或增加管理页 | 指标可定位故障、权限正确，采集不拖累业务 |

## 7. 顺序与交付标准

第一批先完成账号安全闭环；随后逐批推进权限解释、备份恢复、导入和通知体验。其他能力按业务触发，公共能力等复用证据成立后再做。

每批交付相关测试、构建、必要的隔离数据库及页面验收、SQL 执行顺序与回滚说明。分别记录代码完成、本地验收、迁移执行、部署及真实用户验收；没有证据的阶段保持未完成。
