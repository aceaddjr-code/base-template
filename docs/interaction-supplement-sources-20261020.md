# 交互体验与基础档案补充调研

调研始于 2026-10-20，整理补充于 2026-10-21。用途：为[基础模板优化总方案](base-template-optimization-plan-20261020.md)补充表单、键盘焦点、批量操作、组织树及基础档案五组依据。使用 GitHub 插件读取维护方源码及指南；当前仅完成源码核对和方案建议，未修改应用代码，未完成浏览器或辅助技术验收。

## 1. 字段级错误反馈与首个错误定位

### 已核对的一手来源

仓库：`vueComponent/ant-design-vue`，固定提交：`7483836f0adac76516e527df893c3d84a7cd4005`。

- [Form.tsx：提交失败与滚动定位](https://github.com/vueComponent/ant-design-vue/blob/7483836f0adac76516e527df893c3d84a7cd4005/components/form/Form.tsx#L203)：提交失败处理读取 `errorFields`，配置 `scrollToFirstError` 后调用 `scrollToField`。定位通过已注册字段的 DOM ID 完成，滚动代码本身不等于把键盘焦点移入输入框。
- [Form.tsx：字段校验结果](https://github.com/vueComponent/ant-design-vue/blob/7483836f0adac76516e527df893c3d84a7cd4005/components/form/Form.tsx#L326)：失败对象包含 `values`、`errorFields` 和 `outOfDate`；可按字段展示并识别已过期的校验结果。
- [FormItem.tsx：字段反馈接口](https://github.com/vueComponent/ant-design-vue/blob/7483836f0adac76516e527df893c3d84a7cd4005/components/form/FormItem.tsx#L107)：已有 `help`、`hasFeedback`、`validateStatus`，可用于提示、错误和校验中状态。

这些源码证明组件库提供对应能力，不证明本项目当前已正确接入，也不证明外部源码提供了适用于本项目的服务端字段错误协议。

### 本项目现状

- [示例新增表单](../frontend/src/views/examples/items/index.vue)目前使用纵向 `a-form`，标题由 `save()` 手工检查并弹出 `message.warning`；未在该表单配置字段 `name`、规则和首错定位。
- [DetailDrawer](../frontend/src/components/DetailDrawer.vue)使用 descriptions 展示并原位编辑字段；`saveEdit()` 顺序检查必填项，发现错误后给出一条顶部提示。输入控件已有 `aria-label`，保存失败保留编辑内容。
- [用户管理](../frontend/src/views/system/users/index.vue)新增用户也使用顺序校验和顶部提示，已构成与示例页不同的真实调用场景。
- [统一异常过滤器](../backend/src/common/filters/http-exception.filter.ts)把 ValidationPipe 的字符串数组合并成 `message`，响应当前不保留可直接映射到控件的结构化字段错误。

### 适配建议（项目推论）

新增“字段级校验与错误定位”条目，建议 P1。保留纵向新增表单和详情原位编辑，先统一以下行为，再在至少两个真实调用场景中提取共享能力：

1. 必填、格式、长度错误显示在对应字段附近；用户修改后重新校验，错误消失规则一致。前端预校验不替代后端校验。
2. 提交失败时展示简短摘要，展开错误字段所在折叠区或页签，并滚动到第一个错误。需要输入时再将焦点交给对应控件；不能把 `scrollToField` 直接描述成焦点管理。
3. 服务端逐步增加兼容现有响应的字段错误列表，字段路径与表单声明对齐。唯一值冲突、业务规则错误由模块明确映射；无法映射的错误保留为表单级提示，不能从中文提示字符串猜字段名。
4. 当前表单已经显示字段/表单错误时，不再重复弹同一条全局提示；请求号仍可查看。并发校验只采用当前输入对应结果，不能让旧请求覆盖新输入。
5. 保存过程中防止重复提交；失败保留输入并支持修正重试。密码最短 3 位规则继续沿用，不借校验统一修改用户既有要求。

验收：同一次提交可看到全部字段错误；首个错误不被抽屉标题遮挡；页签里的错误可以定位；服务端唯一值冲突落到正确字段；快速修改不会显示旧错误；失败后内容保留；只用键盘可定位并修正错误。

## 2. 抽屉、弹窗和原位编辑的焦点闭环

### 已核对的一手来源

仓库：`w3c/aria-practices`，固定提交：`0f765e4dc33e966026114ac12a8380db1de3b787`。

- [Modal Dialog Pattern：键盘与初始焦点](https://github.com/w3c/aria-practices/blob/0f765e4dc33e966026114ac12a8380db1de3b787/content/patterns/dialog-modal/dialog-modal-pattern.html#L50)：打开模态对话框后焦点进入内部，Tab/Shift+Tab 在内部循环，Escape 关闭；长内容可先聚焦顶部静态标题，避免初次聚焦把开头滚出视口。
- [Modal Dialog Pattern：关闭后的焦点](https://github.com/w3c/aria-practices/blob/0f765e4dc33e966026114ac12a8380db1de3b787/content/patterns/dialog-modal/dialog-modal-pattern.html#L98)：关闭后返回触发元素；元素已不存在时选择符合后续操作的逻辑位置。难以撤销的确认可优先聚焦风险较低的操作。
- [Modal Dialog Pattern：名称与模态语义](https://github.com/w3c/aria-practices/blob/0f765e4dc33e966026114ac12a8380db1de3b787/content/patterns/dialog-modal/dialog-modal-pattern.html#L121)：对话框应有可识别名称；只有实际阻止背景交互时，才应宣告为模态。

APG 是可借鉴的交互模式指南。引用指南和静态源码不足以宣称本项目已经通过无障碍符合性验收。

### 本项目现状

- [全局样式](../frontend/src/style.css)已有 `focus-visible` 和 `prefers-reduced-motion` 支持，应保留并复测。
- [DetailDrawer](../frontend/src/components/DetailDrawer.vue)基于现有 `a-drawer`；保存时关闭遮罩关闭、键盘关闭和关闭按钮，编辑控件也会禁用。组件已有编辑、取消、保存、全屏入口，不能误称没有键盘或可达性基础。
- 当前共享组件没有显式描述“进入编辑后焦点到哪里、保存/取消后焦点回哪里、触发记录被删除后如何恢复焦点”的业务级规则。Ant Design Vue 可能已处理弹层通用行为，实施前需先在真实页面核验，避免重复实现焦点陷阱。
- 详情页签的可选创建入口目前使用 hover 下拉，应检查键盘和触摸是否有等价入口；当前示例是否实际启用该入口须以真实调用为准。

### 适配建议（项目推论）

新增“键盘操作与焦点闭环”条目，建议 P1/P2：先做现有弹窗、共享详情抽屉、菜单搜索的键盘闭环，再扩大到复杂列表控件。

1. 逐场景明确初始焦点：新增进入第一个可编辑字段；长详情先定位标题；危险确认默认聚焦取消。复用组件库行为，仅补缺口。
2. 详情从查看切换编辑后聚焦首个可编辑字段；保存或取消回查看态时聚焦仍存在的“编辑”入口，避免焦点留在被卸载的输入框上。
3. 关闭弹层恢复到原触发按钮；记录已被删除或当前页已变化时，回到相邻记录或列表操作区等合理位置。与总方案已有列表返回恢复配合，不另建一套列表状态。
4. Escape 只影响最上层弹层；有未保存修改时走既定离开提醒。提交中的临时关闭限制应有可感知状态，失败或超时后恢复可操作性，避免永久困住用户。
5. 保留现有焦点可见样式和减少动画设置；图标按钮、只在悬停出现的入口检查可访问名称、键盘及触摸替代操作。不得仅靠颜色传达状态。

验收：只用键盘完成打开详情、进入编辑、修改、保存、重新编辑、取消和关闭；Tab 不落入模态背景；关闭后焦点回到合理位置；触发记录删除后无焦点丢失；嵌套确认只关闭顶层；缩窄视口和放大后控件仍可操作；减少动画设置继续有效。

## 3. 批量选择范围与失败恢复（F37）

### 已核对的一手来源

[Ant Design Vue 行选择源码](https://github.com/vueComponent/ant-design-vue/blob/7483836f0adac76516e527df893c3d84a7cd4005/components/table/hooks/useSelection.tsx)的 setSelectedKeys 根据 preserveSelectedRowKeys 决定是否保留不在当前数据源中的 key，并维护对应记录缓存；未启用时会按当前数据源过滤选择键。这说明跨页保留是明确的配置选择，不是组件自动赋予的全量业务操作权限。

该源码不提供后端逐条执行、授权、失败重试、进度或取消事务协议，以下结果恢复规则属于本项目建议。

### 本项目现状与适配

- [示例列表](../frontend/src/views/examples/items/index.vue)已有选择、批量删除、导出及逐条结果；重新查询会清空选择。[示例服务](../backend/src/modules/example/example.service.ts)的批量删除复用单条删除路径。应保留上限与原授权规则，不能把已有批量功能再计为“从零新增”。
- 首版明确“当前页已选 N 条”；翻页/改条件继续清空。跨页选中、全部匹配记录是不同需求，未来启用时需重新设计查询快照和服务端范围校验。
- 结果分为成功、明确失败和结果待确认；允许查看或下载有权查看的失败明细。同步响应中的明确失败项可重新鉴权、校验状态后重试，成功项不再次提交。
- 超时可能发生在服务端已经写入之后，不能判定整个批次失败并重放。结果未知或需要可靠恢复时，先提供操作编号及查询结果能力；异步化沿用 F09，不另造任务平台。
- 如提供进度，使用实际完成数；客户端关闭窗口不代表后端撤销。后端协作取消最多停止尚未开始的操作，已完成项结果继续保留。

验收：部分成功/失败、权限变化、响应丢失、翻页和改条件后选择变化均有清楚结果；只重试明确失败项；失败详情不泄露无权记录；列表刷新及数据库回读与结果一致。

## 4. 组织树搜索与层级定位（F39）

### 已核对的一手来源

[Ant Design Vue 树搜索示例](https://github.com/vueComponent/ant-design-vue/blob/7483836f0adac76516e527df893c3d84a7cd4005/components/tree/demo/search.vue)使用 searchValue、expandedKeys 与 autoExpandParent；getParentKey 递归查找匹配节点的父路径，查询时展开祖先并在标题中高亮命中词。

该示例针对内存中的完整树，不证明远程部分加载树可完整搜索，也不包含本项目的组织可见范围、人员统计或列表筛选规则。

### 本项目现状与适配

- [部门服务](../backend/src/modules/department/department.service.ts)的 findAll(keyword) 先用关键词裁剪记录，再从空 parentId 构树；若只有子节点匹配，缺少祖先可能使该节点无法进入结果。此处是源码推导，未复现网页故障。
- [用户页](../frontend/src/views/system/users/index.vue)当前通过启用部门全量数据构树，有部门选中及人数信息。新搜索应沿用现有部门与子部门范围规则，不把上述接口推断当成现有用户页已经搜索失败。
- 搜索显示匹配节点与允许展示的祖先路径；节点选择、用户手动展开、搜索自动展开分开管理。清空搜索后恢复合理展开；选中节点被搜索隐藏时仍显示当前生效条件，不静默切到全部人员。
- 若大树改用懒加载，服务端提供完整范围内搜索；不能只搜索已加载节点却声称全树无结果。人数统计与列表使用同一授权和组织范围，不借路径或数量暴露额外信息。

验收：只命中子节点、多分支同名、清空搜索、选中节点隐藏及受限账号；祖先路径完整且可授权展示，筛选条件和人数口径一致。

## 5. 基础档案引用与历史兼容（F40）

### 已核对的一手来源

[RuoYi DictDataServiceImpl](https://github.com/YunaiV/ruoyi-vue-pro/blob/ac022b15a094cf9cf82903d429b9729e72309da5/yudao-module-system/src/main/java/cn/iocoder/yudao/module/system/service/dict/DictDataServiceImpl.java)在 updateDictData 中检查存在性、字典类型和同类型值唯一性，deleteDictData 检查存在性后删除。此处仅证明这些校验，不证明“所有被业务引用的值不可更改”“删除均有业务引用保护”或“停用后自动保留历史名称”。

### 本项目现状与适配

- 当前部门删除已有子部门/用户引用检查，角色删除已有主角色/附加角色引用检查；[字典服务](../backend/src/modules/system/dict.service.ts)删除类型前检查选项。这些基础继续复用，不重新声明为缺失能力。
- 字典 findByCode 仅返回启用类型和选项；[useDict](../frontend/src/composables/useDict.ts)缺少标签时会回退原始值。修改选项值目前检查唯一性，删除选项缺少业务引用规则；历史回显与引用约束由本项目补充。
- 新增选择只给启用项；历史记录的停用值仍可解释并标记停用，不在编辑其他字段时自动清空。后端回读原记录，未改动的原停用值允许保留；新建/主动改选拒绝使用停用值，不能信任客户端自称的原值。
- 已使用的存储值原则上稳定，变更要有实际调用模块的影响检查与迁移。引用规则由拥有业务的模块声明，不扫描未知表猜关系；出现两个真实调用方后再提取公共机制。
- 当前名称与发生时名称快照是不同业务语义，由模块选择。历史解析沿用权限，不默认全系统保存每个字段快照。缺项显示原值的容错继续保留。

验收：停用后的旧单可查看及编辑无关字段；新增或改选停用项被后端拒绝；伪造原值无效；有引用时修改/删除按模块规则阻止或完成明确迁移；历史标签缺失时仍可识别原值。
